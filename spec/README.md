# Pantry — техническое задание

План еды и список покупок. PWA, работает офлайн, устанавливается на Android и iPhone.

## Идея в одном абзаце

Каталог блюд ведётся вручную **прямо в этом репозитории**: приготовил, сфотографировал, положил фото и состав
в код, закоммитил. Приложение показывает каталог сеткой фотографий: дома в два тапа набираешь, что готовишь на
неделе и что взять помимо готовки, — и получаешь список покупок, разложенный по отделам магазина. В магазине
идёшь по этому списку и отмечаешь купленное. План и отметки лежат локально в IndexedDB на устройстве.

## Основной сценарий недели

1. Вечером воскресенья открыл «План» → тапнул «борщ», «плов» и «сырники».
2. Пролистал ниже, добавил хлеб, молоко, корм кошачий, два чебурека.
3. Утром в магазине открыл «Список» → продукты уже сложены по отделам, а граммовки из трёх блюд сведены в одну строку.
4. Идёшь по залу и отмечаешь купленное. Список можно скопировать текстом и отправить тому, кто идёт вместо тебя.

## Принципы

**Офлайн-первый.** Никакого бэкенда, никакой авторизации, никаких сетевых запросов в рантайме. После установки
приложение полностью работоспособно в подвале магазина, где не ловит связь.

**Каталог — это код.** Блюда не создаются из интерфейса. Единственный способ завести блюдо — коммит в
репозиторий. Это осознанное ограничение: состав получает ревью, типизацию и историю изменений, а приложение
остаётся read-only относительно контента.

**Продукты — исключение, и только они.** Разовая покупка вспоминается у полки, а не за компьютером. Свои
продукты заводятся с телефона и живут рядом с планом, а не в репозитории.

**Никаких калорий.** Их считает [calories_count](https://github.com/tednaaa) — отдельное приложение с
отдельным дневником. Дублировать подсчёт здесь значит вести две несогласованные базы одного и того же.

## Границы (чего в проекте нет)

| Нет                               | Почему                                                                 |
| --------------------------------- | ---------------------------------------------------------------------- |
| Бэкенда, аккаунтов, синхронизации | Один пользователь, один телефон. Страховка — экспорт JSON              |
| Калорий, БЖУ, веса                | Этим занимается calories_count                                         |
| Создания блюд из интерфейса       | Размывает каталог и ломает дисциплину коммитов                         |
| Истории закупок                   | Отложено. План — набор строк, закрытая закупка была бы их снимком      |
| Цен и бюджета                     | Ценники меняются быстрее, чем каталог, и врали бы больше, чем помогали |
| Разметки по дням недели           | Плоский план: важно, что купить, а не в какой день это будет съедено   |
